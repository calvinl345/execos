# Context

This developer-only skill guides safe edits to ExecOS system prompt
sources over time. Use it when Calvin asks to change production or developer
prompt behavior, tone, skill routing, safety rules, confirmation behavior, or a
lesson learned from a reported production failure.

Profile source files under `Profiles/` are canonical. The active repo-root
`CLAUDE.md`, `AGENTS.md`, and `SOUL.md` files may be generated by
`node scripts/installer/materialize.mjs apply-profile`; inspect them only when Calvin explicitly asks about
materialized output. Do not make final prompt edits only in generated root files.

# Workflow

Track progress through this workflow for every system prompt editing task.

1. **Determine the requested change.**
   - Classify the request as personality/feel, production operating behavior,
     harness-specific behavior, skill routing, privacy/confirmation/safety,
     error handling, dashboard/task/goal/document/review behavior,
     developer-only instruction, or a bugfix from a reported production failure.
   - Ask a clarifying question only when ambiguity would make the edit risky.
2. **Locate the correct source.**
   - Use `SOUL.md` for voice, stance, warmth, brevity, judgment style,
     confirmation tone, error-handling tone, and high-level boundaries.
   - Use sibling `CLAUDE.md` and `AGENTS.md` files for global operating
     instructions and harness entrypoint behavior.
   - Use only `CLAUDE.md` for genuinely Claude-specific behavior and only
     `AGENTS.md` for genuinely Codex-specific behavior.
   - Use a skill file when the change is task-specific procedure rather than a
     global operating rule.
   - Use README or docs when the change is human-facing documentation rather
     than agent behavior.
3. **Preserve sibling parity.**
   - Production operating behavior normally changes both `CLAUDE.md` and
     `AGENTS.md`.
   - Diverge only for real harness differences such as import behavior, slash
     commands, context attachments, or tool/shell availability.
   - Document intentional divergence in the file so future maintainers do not
     normalize it away.
4. **Keep `SOUL.md` clean.**
   - Keep it focused on personality, feel, stance, conversational judgment, and
     high-level boundaries.
   - Do not turn it into a command manual, policy dump, changelog, workflow
     checklist, schema note, installer guide, or edge-case archive.
5. **Apply the checklist.**
   - Read `CHECKLIST.md` in this skill before finalizing prompt edits.
   - Use it as a regression checklist, not as content to paste wholesale into a
     prompt file.
6. **Make the smallest safe change.**
   - Prefer targeted edits over full rewrites unless Calvin asks for a rewrite.
   - Preserve existing behavior, especially privacy, confirmation, safety,
     task, goal, document, review, dashboard, memory, and error-reporting rules.
   - Consolidate duplicate rules only after verifying the behavior remains
     covered elsewhere.
7. **Validate after editing.**
   - Self-review whether each edit belongs in the file changed.
   - Check `CLAUDE.md`/`AGENTS.md` parity, `SOUL.md` focus, developer/production
     separation, safety coverage, and prompt maintainability.
   - If editing the currently active developer profile, materialize with
     `node scripts/installer/materialize.mjs apply-profile --profile developer`
     unless Calvin asked for source-only changes.
   - If editing production profile sources while the checkout is in developer
     mode, do not materialize production over the active workspace unless Calvin
     explicitly asks.
8. **Update the checklist with approval.**
   - Identify any durable regression checks that could be added to
     `CHECKLIST.md` based on the change, especially lessons from production
     failures.
   - Present proposed checklist additions or edits to Calvin for approval before
     changing `CHECKLIST.md`.
   - If Calvin approves, update `CHECKLIST.md`; if not, leave it unchanged and
     mention that decision in the final summary.
9. **Summarize precisely.**
   - Report files changed, why each changed, behavior added or changed,
     intentional Claude/Codex differences, checklist areas affected, validation
     performed, and any TODOs or follow-up tests.

# Gotchas

- Active repo-root prompt files may be generated output. Edit `Profiles/`
  sources unless Calvin explicitly asks to inspect generated output.
- Do not put task-specific procedure into global prompts when a skill can own
  the workflow.
- Do not weaken privacy, confirmation, external-side-effect, destructive
  database, or sensitive-document protections while simplifying prose.
- Do not let `SOUL.md` accumulate commands, schema details, implementation
  notes, or every historical edge case.
- Do not make sibling prompt files drift silently. Equivalent behavior should
  read equivalently; necessary divergence should explain itself.

# Final Verification

Before replying, confirm:

1. The edited files were source files under `Profiles/`, or generated output was
   only inspected by explicit request.
2. The change belongs in `SOUL.md`, sibling prompt entrypoints, one harness
   entrypoint, a skill, or docs according to the request.
3. `CLAUDE.md` and `AGENTS.md` remain aligned except for documented
   harness-specific differences.
4. `SOUL.md` remains focused on voice and stance.
5. Production and developer profiles remain separated.
6. Safety, confirmation, privacy, data hygiene, and failure-handling behavior
   were not weakened.
7. The checklist in `CHECKLIST.md` was used before finalizing.
8. Potential `CHECKLIST.md` updates were identified and either approved before
   editing or explicitly left unchanged.
